# AsapOptim v1.5.0

Load cases on Asap's case table: design-dependent shell surface loads in `LoadCases`. Requires
Asap 1.5.

## Changed
- `LoadCases` is now a thin wrapper over Asap's `CaseLoads` (`Asap.case_loads`), and
  `solve_cases` calls Asap's per-case load path. Every case's design-dependent loads follow the
  design: frame line and point loads and self-weight as before, and now quadrilateral and triangle
  shell surface loads too (self-weight ∝ thickness, pressure ∝ area and orientation). The
  refusal of design-dependent shell loads is gone.
- Fields: `LoadCases` gains `cl` (the Asap case table) and `Eel` (frame load → element
  incidence); `E` now lists the frame loads in `cl.fef` order; the dense `M` mask is gone (Asap
  places every case's fixed-end forces with one sparse product). Code that reads `names`, `P`,
  `F`, `static` or `qa0` is unaffected.
- Zygote gradients through `solve_cases` use Asap's linear-cost case-load rules (the previous
  frame-load map had no rule of its own).

## Verified
- Every case against one `OptParams` per case (U, F, compliance, axial force and stress), frame
  portal and a quadrilateral/triangle wall with thickness variables, design and frozen loads;
  Zygote ≡ ForwardDiff ≡ the sum of the single-case gradients.

## Compatibility
- Existing problems give the same results as 1.4.
