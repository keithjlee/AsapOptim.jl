# AsapOptim v1.0.0

A ground-up rewrite on Asap v1.1's differentiable core. AsapOptim is no longer a parallel implementation of structural analysis with hand-written adjoints — it is a thin design-vector layer (~700 lines): variables compile into sparse scatter maps, designs evaluate through Asap's pure `ModelState → solve` path, and gradients flow through any modern AD engine with **zero custom rules in this package**. One unified core serves trusses, frames, semi-rigid joints, and force-density networks; every derivative path is verified against finite differences and cross-checked between independent AD engines.

## New features

**One parameter type, freely mixed variables**
- `OptParams(model, variables)` for every model — `TrussOptParams` and `FrameOptParams` remain as aliases, and `solve_truss`/`solve_frame` alias the unified `solve_structure`.
- Variable types **mix freely in one problem** on models mixing truss and frame elements: spatial + area + joint-stiffness variables with arbitrary couplings, gradient-verified in a single `OptParams` ("kitchen sink" suite test).
- `SpatialVariable` (additive nodal offsets), `AreaVariable` (absolute section area — frame elements included, via Asap's parametric section promotion), and **new `JointVariable`**: semi-rigid rotational connection stiffness (`ky = kz`, at `:start`/`:end`/`:both`) as a design variable — connection-cost optimization is now a smooth problem (see `examples/joint-stiffness.jl`).
- `CoupledVariable(target, parent, factor)` expresses symmetry and grouping by *sharing design entries* (mirrored geometry via `factor = −1`, member groups, mirrored joint pairs via `(element, position)` tuple targets) — equality constraints for free, with the factors compiled into the scatter maps so every derivative path honors them automatically.
- Ill-posed declarations error at compile time with descriptive messages: duplicate variables on one element, couplings to non-independent parents, joint variables on element-loaded members (stale fixed-end forces), type mismatches.

**Bring your own AD engine — with a measured playbook**
- No rrules here: loading Zygote (or anything ChainRulesCore-aware) activates Asap's rule extension. **Zygote, Mooncake, Enzyme (reverse and forward), and ForwardDiff** all work through the same code, agreeing to machine precision.
- The guidance, from the benchmark matrix in `docs/AD_BACKENDS.md`: **reverse mode for scalar objectives, forward mode for constraint Jacobians** — a forward Jacobian costs the same as a forward gradient, so ForwardDiff beats reverse by two orders of magnitude on constraint blocks.
- The pipeline is forward-mode native end-to-end: `ModelState` eltype follows the design vector, so ForwardDiff Duals traverse geometry, sections, joints, and the FDM path (the Dual sparse solve lives in Asap's `AsapForwardDiffExt`).

**Implicit differentiation: exact constraint Jacobians at solver speed**
- `solution_tangents(x, p)` computes the full `∂U/∂x` by the implicit-function theorem — one assembly, one factorization, one multi-RHS back-substitution — with `axial_force_jacobian`/`axial_stress_jacobian` chaining the closed-form output terms, and displacement rows sliced directly from `t.dU`.
- ~10× faster than a prepared ForwardDiff Jacobian (3.9 ms vs 39 ms on a 512-element × 512-variable spaceframe) with ~20× less allocation; parity ≤ 2×10⁻¹⁴ against ForwardDiff *and* Zygote on mixed problems including joints and couplings.
- Built generality-first: the only closed-form fast path is the provably linear truss-area case; every other variable — spatial, frame area, joint springs, and future section-property variables — flows through a generic one-partial Dual seed of the *same* element kernels the solver uses. No code enumerates variable types.

**Linear-solver selection and factorization sharing**
- `OptParams(model, vars; solver = ...)` threads a backend through every solve — values, reverse adjoints, forward tangents: built-in CHOLMOD (`nothing`), any LinearSolve.jl algorithm (KLU, Krylov, … via Asap's extension), or `Asap.CachedSolver()`.
- `CachedSolver` shares one factorization across everything evaluated at a design iterate (objective gradient, constraint Jacobian, every ForwardDiff chunk), refactorizing numerically on the frozen symbolic analysis when the design moves.

**Results as plain, differentiable data**
- `OptResults`: full 6-DOF/node displacement vector `U`, positions `X` (3 × n), areas, lengths, sections, and axial rigidities — any scalar of these differentiates back to the design vector.
- `axial_force`/`axial_stress`/`compliance` extend Asap's own accessor names on `OptResults`; element geometry evaluates as batched incidence matmuls (a handful of AD graph nodes, not one closure per element).
- `GeometricProperties(x, p)`: positions/lengths/areas with **no structural solve** — the right cost for volume-style objectives.
- `updatemodel(p, x)` materializes a design back into a solved `Asap.Model` (positions, sections, joint stiffnesses), ready for recovery, visualization, export.

**Force-density (FDM) network optimization, on Asap v1.1's rewritten Network**
- `QVariable` → `NetworkOptParams` → `solve_network` → `NetworkOptResults`, with `member_forces`; grouping via `CoupledVariable`; forward parity with Asap's FDM solver at 1e-10; gradients via the multi-RHS solve adjoint; ForwardDiff-capable; solver-selectable.

**Examples, docs, tests**
- Five end-to-end **executed** examples: compliance geometry (`truss-optimization1`), constrained minimum volume (`truss-optimization2`), the recommended NLopt-direct mixed-AD pattern (`truss-optimization3-nlopt` — reverse objective + forward constraint Jacobian + CachedSolver, ~9× faster per run than the all-Zygote formulation), Vierendeel frame geometry (`vierendeel-geometry`), and semi-rigid connection design (`joint-stiffness`), plus `examples/ad_backends/` for Zygote/Mooncake/Enzyme.
- Engineering reports with reproducible scripts in `docs/`: AD verification vs the publication stack, the backend × Julia-version × task benchmark matrix, and the head-to-head against the DiffAnalysis_2024 published benchmark (below).
- 71 tests: design-vector plumbing, bit-parity of the optimization path with direct Asap solves, Zygote-vs-finite-difference gradient checks on every variable type and path, ForwardDiff-vs-Zygote parity, implicit-diff parity, solver-backend invariance, and the mixed-everything kitchen-sink problem.
- Every exported type and function carries a full docstring; every user-facing type prints an engineer-readable REPL summary.

## Performance

Measured on the DiffAnalysis_2024 S4.2 benchmark spaceframe (145 nodes / 512 elements), Julia 1.11, Apple Silicon; "legacy" is the registered v0.1.3 stack with its fully hand-differentiated adjoints:

| Quantity | legacy v0.1.3 | v1.0 |
|---|---|---|
| compliance gradient (512 area vars) | 0.83–0.94 ms (Zygote) | 1.34 ms Zygote / **0.83 ms Enzyme** |
| stress-constraint Jacobian (512 × 512) | ~400 ms (Zygote) | 43 ms ForwardDiff / **3.9 ms implicit** |
| published gb_mma optimization (540 mixed vars, 596 constraints, MMA) | 552 ms/iter; 548 iterations in the 300 s budget | **57 ms/iter; the full 1000-iteration cap in 56.8 s**, best feasible objective of all runs |

The generality trade against hand-written adjoints costs nothing at the workflow level: reverse gradients match legacy speed (Enzyme) or run within 1.6× (Zygote), and constraint Jacobians — the cost that dominates constrained optimization — are up to 100× faster than the legacy stack via implicit differentiation.

## Breaking changes

This is a clean break from v0.1.x, tracking Asap's own v1.0 break. The legacy implementation is preserved (unloaded) in `legacy_v0/` for reference. Requires **Asap ≥ 1.1**; ForwardDiff is now a direct dependency.

| v0.1.x | v1.0 |
|---|---|
| `TrussOptParams` / `FrameOptParams` (separate types, separate pipelines) | one `OptParams` (the old names still work as aliases) |
| `TrussVariable` element type | `AbstractVariable` |
| `SpatialVariable(node, vector, val, lb, ub)` directional "rail" | axis form only: `SpatialVariable(node, val, lb, ub, :X/:Y/:Z)` |
| `res.U` with 3 DOFs/node (`U[2:3:end]` vertical) | full 6 DOFs/node — y-displacements `U[2:6:end]`, z `U[3:6:end]` |
| `res.X`, `res.Y`, `res.Z` vectors | `res.X` is a 3 × n matrix |
| `res.K`, `res.R` (element stiffness/transformation matrices) | gone — pure results only (`U`, `X`, `A`, `L`, `sections`, `EA`) |
| `params.P` load vector | `params.F` (or just `compliance(res, params)`) |
| `GeometricProperties` with `X/Y/Z/evecs` | `X` (3 × n), `L`, `A` |
| `NetworkResults` | `NetworkOptResults` (Asap owns the `NetworkResults` name) |
| hand-written rrules throughout | none — Asap's rule extension covers everything |

## Known gaps (deliberate, documented)

- `SectionVariable` (parameterizing `Ix`/`Iy`/`J`) is not yet ported; `RigiditySection`-based parameterization is the intended idiom, and the implicit-diff machinery is already structured to absorb section variables with zero new derivative code.
- `NetworkOptParams` rejects per-axis (mixed) FDM node fixity — the differentiable path solves all three coordinates against one partition.
- `solution_tangents` is a plain-`Float64` optimizer-callback path, not itself AD-transparent (differentiate `solve_structure` instead).
- Enzyme quirks (upstream): forward mode requires Julia 1.11 and the default solver; the extension needs ChainRulesCore loaded alongside Enzyme. See `docs/AD_BACKENDS.md` for current per-version status.
