# AsapOptim v1.2.0

Element loads follow the design. Requires Asap 1.2.

## Fixed: gradients on frames with element loads

`OptParams` used to snapshot the load vector `F = P − Pf` once, so
element-load fixed-end forces never followed the design. Every variable that
changes them got a gradient without the load path. These cases were
**silently wrong**:

- `SpatialVariable`s moving the nodes of a member that carries a line,
  point or moment load: the member's total line load and load orientation
  change with its geometry.
- `AreaVariable`/`SectionVariable(:A)` on a member with `SelfWeight` (ρA).
- `SectionVariable(:Ix/:Iy)` on a loaded member with semi-rigid ends (the
  end-moment condensation uses EI).

The fourth case, `JointVariable` on a loaded member, was refused at
`OptParams` time.

Measured compliance gradients, as the ratio of AsapOptim 1.1 to central
differences of rebuilt and re-solved models:

| Case | Ratio |
|---|---|
| cantilever length of a Gerber beam (line loads) | −34.7 |
| gridline position of a multistory braced frame (beam line loads) | −0.025 |
| area of a beam with self-weight | −0.008 |

All three ratios are now 1.000.

## Changed

- **`F(x) = P − Pf(x)`** is evaluated per design through Asap 1.2's
  `assemble_Pf`. Line loads are per-unit-length intensities whose total
  follows the current member length. Point forces and moments keep their
  fractional position. `SelfWeight` follows ρA·L. `:local` directions rotate
  with the member. Condensed end moments follow joint springs and EI.
- **`JointVariable` on loaded members is allowed**. The guard is removed, and
  κ is differentiated through the condensed fixed-end forces.
- **`axial_force(res, p)` includes the element loads' axial component
  `q̃₇`**, matching Asap's stateful `axial_force(res, el)`: slot 7 of
  `f = k·u_local + q̃`, the axial action at the end node. Previously it
  returned only `EA/L·(x̂·Δu)`, which is wrong for inclined loaded members and
  columns under self-weight. `axial_stress` and `axial_force_jacobian` follow.
- **`solution_tangents`** solves `K du = −(∂K/∂x·u + ∂Pf/∂x)`. The same
  one-partial seed per kernel input now runs through both the stiffness and
  the fixed-end-force kernels, so no per-variable code was added. Tangents
  and the axial Jacobian match ForwardDiff.
- **`OptResults` gains `F`** (the design's own load vector) **and `ends`**,
  appended last. `compliance(res, p) = sum(res.F .* res.U)`.

## Added

- `OptParams(model, vars; loads = :frozen)` keeps the base-design load
  vector (the old behavior) for studies where the load is fixed in space.
  New fields: `P` (nodal loads), `loads`, `qa0` (base-design axial `q̃₇`),
  `Eload` (element × load incidence).

## Performance

- No change without element loads, because the constant-load path keeps
  its concretely typed solve call. On an 8×8 spaceframe with 576 variables,
  the Zygote ∇compliance takes 1.10 vs 1.07 ms and `solution_tangents`
  2.6 vs 2.7 ms (noise).
- With element loads, each loaded member adds one kernel closure under
  reverse mode. On a 190-element frame with 80 loaded beams, the Zygote
  gradient goes from 110 to 182 ms (Asap 1.2 notes). This is the same
  per-element cost the frame stiffness path already pays.

## Tests

The new `design-dependent element loads` testset uses an inclined portal
with every dependence: geometry, self-weight area, beam Ix with semi-rigid
ends, and a coupled joint pair. It checks:

- value and axial-force parity with rebuilt models;
- Zygote and ForwardDiff gradients against rebuilt-model central
  differences;
- `solution_tangents` and the axial/stress Jacobians against ForwardDiff;
- the `:frozen` semantics.

The JointVariable testset now checks loaded-member κ gradients instead of
the removed guard.

Downstream: AsapHarmonics' suite runs against this (lockstep). Its
`axial_force(res, p)` consumers see the `q̃₇` term only on element-loaded
frames.
