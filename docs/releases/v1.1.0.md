# AsapOptim v1.1.0

Two variable-system additions: the directional-rail `SpatialVariable` from
v0.1.x (which had not survived the v1.0 rewrite), and the long-planned
`SectionVariable` for flexural/torsional section properties.

## New features

**`SectionVariable`: flexural and torsional section properties as design variables**
- `SectionVariable(element, value, lb, ub, property)` with `property` ∈
  `:A`, `:Ix`, `:Iy`, `:J` — absolute semantics like `AreaVariable`
  (`:A` routes to the same machinery; the flexural/torsional properties
  require a `FrameElement`). The convenience form
  `SectionVariable(element, lb, ub, property)` starts from the section's
  current value (legacy v0.1.x API shape).
- Mixes freely with every other variable type and coupling — the suite
  drives all five variable kinds in ONE `OptParams` and verifies gradients
  across Zygote, ForwardDiff, and finite differences.
- Works with implicit differentiation out of the box: section-property
  pseudo-loads go through the same generic element-local kernel seed as
  every other variable — zero new derivative code, parity ≤ 1e-9 against
  full-pipeline AD.
- Zero cost when unused: problems without section variables evaluate
  exactly as before (re-verified against all benchmark baselines).

**Directional "rail" spatial variables**
- `SpatialVariable(node, vector, value, lb, ub)` — the node travels along
  an arbitrary direction: `x′ = x₀ + value · unit(vector)`. The direction
  is normalized at construction, so `value`/`lb`/`ub` are arc-length along
  the rail (exact legacy v0.1.x semantics). The 4-arg
  `SpatialVariable(node, vector, lb, ub)` convenience (starting value 0)
  is also back.
- The axis form `SpatialVariable(node, value, lb, ub, :X/:Y/:Z)` is now the
  unit-vector special case (lowercase axis symbols accepted).
- Rails work everywhere axis variables do, with no carve-outs: `Zygote`,
  `ForwardDiff`, implicit differentiation (`solution_tangents` and the
  constraint Jacobians), `CoupledVariable` mirrors/groups, and
  `updatemodel` — the direction components enter the compiled position
  scatter map as the `∂X/∂x` factors, so every downstream path inherits
  them structurally. All paths gradient-verified in the suite.

## Changed

- `SpatialVariable`'s `axis::Symbol` field is replaced by
  `direction::SVector{3,Float64}` (a unit vector). The documented
  constructors are unchanged; only code reading the `.axis` field directly
  (undocumented usage) needs to switch to `.direction`.
